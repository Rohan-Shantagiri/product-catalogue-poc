This specification expands [the Phase 1 requirements](PLAN.md#16-work-plan-phase-gated). Phase 1 already existed when this specification was written. Its checks combine the original tests, new regression tests, and repeatable smoke checks.

## Automated checks

Run `npm ci`, `npm run verify`, and `npm run build` with Node 24. The automated tests use local fixtures and intercept browser requests with MSW.

## Developer smoke check

1. Run `npm run dev` with Docker running. To exercise overrides, set `PORT=13000`, `SMTP_PORT=11025`, and `MAILPIT_UI_PORT=18025` in the environment first.
2. Open the URL printed by Vite and check that the status is `API: ok`. Request `/api/health` both through Vite and on the API port. Both must return `{"status":"ok"}`.
3. Confirm that Mailpit loads on the selected UI port and its SMTP mapping listens on loopback. Stop the development processes and run `docker compose -f docker-compose.yml -f docker-compose.dev.yml down`.

## Compose smoke check

1. In a fresh checkout with the Phase 1 changes, time `docker compose build --no-cache --pull` followed by `docker compose up -d --wait`. The stack must be ready within 10 minutes.
2. Open <http://localhost:8080> in a browser and expect `API: ok`. Open <http://localhost:8025> and expect the Mailpit UI. Request `/api/health` on ports 3000 and 8080 and compare the status and payload.
3. Inspect API and web container settings for the hardening in P1-07. Inspect Mailpit's port bindings and confirm that 1025 is only available inside the stack.
4. On port 8080, check the CSP, `X-Content-Type-Options`, and `Referrer-Policy`. Confirm that the proxied health response has `X-Request-Id` and `Cache-Control: no-store`. Request a deep URL such as `/catalogue/example`, verify the shell HTML is returned with `no-cache`, and request the emitted asset to verify its immutable cache header.
5. Run `docker compose stop api` and confirm the API logs a SIGTERM shutdown and exits with code 0. Run `docker compose down` and confirm the stack is removed.
