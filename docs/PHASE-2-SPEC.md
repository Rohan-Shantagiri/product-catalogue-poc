## First task · Shared contracts

- A product with ID `SKU_A-2`, price `10995` cents in `AUD`, and image path `/api/v1/products/SKU_A-2/image` parses without converting the ID or price. The `rating` field accepts a star average plus review count or `null`.
- Numeric IDs, malformed slugs, fractional or negative cents, invalid currency and rating values, external image URLs, and leaked upstream fields fail validation. Product IDs follow D6. Category slugs follow D7 and the route grammar in §6.
- Product and category collection responses use `{ items }`, which allows an empty list. Category-product responses require `category`, `topRated` and `others`.
- Problem details retain the Phase 1 response shape and accept the full API code list, optional detail and request ID, and optional field errors. Unknown codes, malformed field errors, and internal stack properties fail validation.
- Test all these examples through the contracts workspace's public exports. Run `npm run test -w @catalogue/contracts` for this task and `npm run verify` for the repository gate.

## Remaining tasks · Acceptance examples

- **Rules.** Plan §16.1 fixes the catalogue and search ordering. Test prefix matching, accents, apostrophes, plural handling, empty tokens, curated order, no overlap, and fallback ties. Test D5 conversion with 109.95 and 0.29, and D7 with men's clothing and Jewelery.
- **Sources.** Both repositories implement the same five operations. Lookups preserve opaque IDs and input order, categories are sorted, and unknown IDs and slugs return null where specified. Fake Store retries a network error or a 5xx once and skips invalid rows with a warning. Test single-flight, TTL, recovery after failure, and stale serving with an injected clock. Merchandising validates the file at startup, including unique curated IDs and the fallback range.
- **HTTP.** Run the §16.1 cases against fixture mode and Fake Store mode with a stubbed upstream for deterministic tests. Parse JSON responses with shared contracts. Verify cache policy, request IDs, validation failures, safe 404 and 502 responses, logging of fallback and missing picks, and route-template logging.
- **Images.** Verify GET and the host allowlist, prevent redirects, and enforce the content type and 5 MiB cap even when the response omits its length. Test the 50-entry cache, read the bundled SVG offline, and compare result types in both modes.
- **Manual verification.** Record the fixture using the snapshot command. Start both modes and check the §16.1 responses, including real PNG and local SVG where the live provider is reachable.
